# Takewise reference

The details behind the [README](../README.md): every command's options and refusals, the start window and the menu bar, recording passages, the audio panel, the setup check, the export and building from source. The design and its reasons are in [design.md](design.md); an agent's whole loop, with the exact JSON, is in [agents.md](agents.md).

## Command line

Most commands take the project directory first; `models` takes none, and `doctor`'s is optional. With `--json` a command prints one JSON object on stdout: `{"ok":true,"data":…}`, or `{"ok":false,"error":{"code":…,"message":…}}` with the data that led to it. Exit codes: 0 success, 1 a finding (an export that refuses, `status --strict` with problems, a failed `doctor` check), 2 a usage or setup error.

```sh
# Measure the film, create an empty script
takewise init promo.takewise --film renders/promo.mp4
# Agents write the [[line]] tables
$EDITOR promo.takewise/script.toml
# Lines, takes, verdicts, proposed and chosen takes, problems
takewise status promo.takewise
# Change one field of one line, keeping comments
takewise script set promo.takewise hook --start 1.5
takewise judge promo.takewise hook 2 --verdict keep \
  --reason "clear, warm" --by claude-opus-5-5 --score 0.8
takewise choose promo.takewise hook 2 --by claude-opus-5-5
# Choose every take that was cut from one passage
takewise choose promo.takewise --passage <id> --by claude-opus-5-5
# export/narration.wav (or .flac) and export/manifest.json
takewise export promo.takewise
# Open the recording window in Takewise.app
takewise record promo.takewise
# Loopback test: store latency_offset_ms
takewise calibrate promo.takewise --write
# Tools, the model, the microphone and the devices; with a project
# also its film and its input device
takewise doctor [promo.takewise]
# Whether the speech model is installed
takewise models status
# Download and verify it (1.5 GB), resuming
takewise models install
```

- `status --strict` exits 1 while a line has no chosen take or any problem exists; `--repair` adopts takes a crash left without a ledger event, finishes a passage a crash interrupted and cuts published passages that still lack their takes; `--refresh-film` re-measures a film that changed. Notices, which do not fail `--strict`, include `calibration-stale` (the input, the output or the capture buffer differs from the ones the latency was measured on), `no-setup` (no setup check has run yet) and `setup-changed` (the devices changed since the setup check); for any of these, press C in the recording window. `calibration-remembered` only informs: the offset in use was copied from an earlier measurement on these devices (see [Remembered across projects](#remembered-across-projects)). `rescued-audio` names a folder with audio the window could not save into this project, and how to bring it back (see [Rescued audio](#rescued-audio)).
- Passages. Consecutive lines whose slots lie less than `[record] passage_gap_s` (1.0 s) apart form a passage: line *k* and the next belong together while `next.start − slot_end(k) < passage_gap_s`. `status --json` gives each line its `passage`, the id of the passage's first line; set `passage_gap_s = 0` to make every line a passage of its own. A passage recorded in one go is kept whole in `takes/.passages/<id>.wav` (with its sidecar `<id>.json`: the lines, where its first sample lies on the film, and the cuts) and cut into one ordinary take per line; such a take has a `passage` object in `status --json`: `id`, `index` and `count` (which piece of how many), `from_sample` and `to_sample` (its range in the passage file) and `preroll_floor_dbfs`. `choose <dir> --passage <id>` chooses the take of every line the passage has one of: all of them, or none when a take's file is missing (exit 1, `missing-file`) or the passage is not cut into all its takes yet (exit 1, `passage-not-split`; run `status --repair`); an id no take belongs to exits 2 (`unknown-passage`). Its `--json` output names the takes `chosen` and the lines `skipped`, each with the `reason` (the passage has no take of that line, or the line left the script); skipped lines keep their choice. Notices about passages: `partial-passage` (a recording was interrupted; `status --repair` finishes it), `passage-unplaced` (interrupted before it was placed on the film: kept, with its path, and never cut), `interrupted-passage` (interrupted while being saved; said once, without a `partial-passage` for its audio) and `passage-not-split` (published, takes still missing); `status --repair` settles all but `passage-unplaced` and reports what it did in `repair.passages_published`, `repair.pieces` and `repair.passages_unplaced`, and in `repair.passages_failed` any passage it could not finish, with the reason.
- `script set` takes exactly one of `--text`, `--start`, `--end`, `--note`, `--clear-end` and `--clear-note`. Pass `--expect <script_version>` from `status --json` to refuse the edit if the script changed since you read it.
- `export` uses each line's chosen take and places it at the line's current start plus the offset the take was recorded at, trimmed to its detected speech with a 150 ms margin; moving a line's start moves its take with it. Lines whose chosen takes are consecutive pieces of one passage, still placed as recorded, are exported as one stretch, as the passage was recorded: trimmed and faded only at its two outer ends, with no cut between the lines, cleaned as one file by `clean`, and marked in the manifest with `seam_with` (the next line's id) on each line joined to the next. Moving one of those lines, or choosing another take for it, cuts it from its neighbours as any two takes are; the other lines stay joined. It refuses, naming the lines, when a line has no chosen take, when a take it uses has no detectable speech, or when two takes' speech overlaps in the film. Lines joined as one stretch need speech in one of them only: when a line was read early or late, into its neighbour's piece, its own piece holds just the room, and the export goes ahead with a `passage-piece-without-speech` warning that names the line. When that piece is first or last in its stretch and the passage's piece on that side is not exported (its line uses another take), the warning says the line may be missing from the export and names that piece's take file, where its words likely are; the piece itself is trimmed away whole, and its ranges in the manifest are empty. It also refuses when the film is missing (`film-missing`) or changed since it was measured (`film-changed`: its size, modification time or duration differ; check the timings, then run `status --refresh-film`; the film is probed again just before the files are published, so one replaced during the export refuses too), and when the project changed twice while it rendered (`state-changed`; export again). `--use-proposed` fills unchosen lines with the proposed take, and still refuses a line whose proposed take is marked `retake` (`no-acceptable-take`). `[export]` in `project.toml` sets the file, and `--format wav|flac`, `--bit-depth 16|24`, `--sample-rate 48000|44100` and `--processing raw|clean` override it for one export. `raw` places the takes as recorded. `clean`, the default for projects made by `init`, high-passes each take at 80 Hz, reduces its noise by up to 10 dB when a room tone from the setup check matches it (a `noise-reduction-skipped` warning says per line when and why it did not), and brings the narration to −16 LUFS integrated (a common level for spoken word) with one gain and a transparent look-ahead peak limiter that keeps the true peak below −1 dBTP; the limiter never takes more than 6 dB, so very dynamic narration can stay below the target (`loudness_target_reached: false` and a `loudness-target-missed` warning). The manifest records the measured loudness and true peak of the final file. Takes are never changed. 16-bit files are dithered. `ffmpeg` is needed for `clean`, 44.1 kHz and FLAC; `raw` WAV at 48 kHz works without it. A project without `[export]` exports 48 kHz 24-bit WAV, `raw`. Only one narration file sits beside the manifest: switching the format removes the other.
- `record` refuses a script with validation problems (exit 1) and exits 2 when no `Takewise.app` is found. In the window: Space records or stops a take of the current line: the film starts `[record] preroll_s` (3 s; projects made before 0.1.2 keep the 2 s they were made with) before the line with a 3-2-1 count-in over its last three seconds, the line fills at an even pace across its slot, and the take runs until you stop it or `[record] tail_s` (1.5 s) after the slot ends. A line's slot runs from its start to its `end`, else the next line's start, else the film's end. Enter chooses the selected take, R records another, P plays the line in context with the take locked to the film, M sets the line's start to the playhead while the film plays (during a take of one line or P; it stays between the previous line's start and the slot's end), E edits the line's text, ↑/↓ move between lines and ←/→ between takes. A line longer than three rows scrolls with the pace guide, keeping the current words on the middle row. The line list scrolls to keep the current line in view and shows each passage of several lines with a thin bar beside them. With Shift the same keys work on the passage (see [Passages in the window](#passages-in-the-window)). The audio keys are described [below](#sound-the-audio-panel-and-meters), and C opens [the setup check](#the-setup-check) (L its latency step alone). The window records only from the project's `[input] device` at 48 kHz and says why when it cannot. It reloads when `script.toml` or `takes.jsonl` change, and refuses an edit made against a script that changed on disk. Closing it mid-take keeps the take. While a take or passage could not be saved and exists only in memory (a full or failing disk), the window does not close and ⌘Q does not quit: it says how many are unsaved and why, keeps trying to save them every two seconds, and closes when you close it again after freeing disk space or fixing the problem. If the problem cannot be fixed (the project's disk is gone), close it again anyway: the window then writes a rescue copy of that audio outside the project and closes (see [Rescued audio](#rescued-audio)). Quitting from the Dock, or logging out, does not ask first; the window then saves what it can and writes the rescue copy on its way out.
- `calibrate` plays ten short beeps (a short film made with `ffmpeg`, played with seeks backwards and forwards) through `--output <device>`, else the project's `[output] device`, else the system output, while the project's input records them in Takewise.app; hold the headphones to the microphone. It prints where the beeps landed (mean and standard deviation in ms) and with `--write` stores the offset that cancels the mean in `[input] latency_offset_ms`, with the input, output and capture buffer size it was measured on in `[calibration]`, keeping `project.toml`'s comments; the offset is also remembered for other projects on exactly these devices and buffer size (see [Remembered across projects](#remembered-across-projects)). Fewer than six detected beeps exits 1. Calibrate again whenever `status` or the audio panel says the calibration is stale.
- `check` runs the checks (energy speech detection, whisper-cli words, sound, timing, background noise) on every take without a current check and appends a `checked` event each; `--line` and `--take` re-run those takes even when checked, `--stale-only` only those checked against older text or an older slot, or transcribed by another model (`[check] whisper_model`) or preprocessing. Whisper hears a copy high-passed at 60 Hz and peak-normalized; the take is never changed. A take cut from a passage is checked with the noise floor of the passage's pre-roll, and its timing rules follow its place in the passage: overrun counts only on the last piece and early start only on the first, a later piece whose words start more than 1.0 s from its line's start gives `listen` (`passage-drift`), and a piece beside a cut that found no pause gives `listen` (`passage-boundary`: the words may be split between the two lines). A missing whisper-cli, ffmpeg or model exits 2 with how to install it.
- `models install` downloads `ggml-large-v3-turbo.bin` from whisper.cpp's repository on Hugging Face into `~/.local/share/takewise/models` (or `$TAKEWISE_MODELS`), resumes an interrupted download, and installs it only when its size and SHA-256 match the ones pinned in Takewise. The recording window offers the same with a button (I) while the model is missing; until it is there, takes are checked without words (`listen`, "words not checked") and their words are checked once it is installed.
- `doctor` lists the input devices with their sample rates and channels, checks the project's input device (chosen, connected, at 48 kHz), and warns when the output is Bluetooth.

The project folder is plain TOML, JSONL and WAV; see [Project folder](design.md#project-folder) in the design.

What needs which tool: `init` and `status --refresh-film` measure the film with `ffprobe` (part of `ffmpeg`); the word checks need `whisper-cli` and the speech model; `clean` export, FLAC and 44.1 kHz need `ffmpeg`. In an existing project, recording, choosing and `raw` WAV export at 48 kHz work without `whisper-cli` and `ffmpeg`.

The word checks hear the language in `[check] language` (`en` by default), passed to `whisper-cli` as is, so any Whisper language code works; the matching of numbers and contractions against the script is tuned for English.

## The start window

Opening `Takewise.app` from the Dock or Finder shows the start window. **Open project…** (⌘O) opens a `.takewise` folder; any other folder asks for the finished film and starts a project there, in a new `<film>.takewise` folder inside it, unless the folder is empty or named `….takewise`. If that `<film>.takewise` project exists already for this film, it opens; if it belongs to another film of the same name, the new project is named after the film's full file name (`Promo.mov.takewise`). Recent projects are listed below; a project that is already open comes to the front instead of opening twice.

## The menu bar

The menu bar is the same in the start window and every recording window:

- **Takewise:** **About Takewise** (the standard About panel: version and build, what Takewise is, and a link to the repository), **Install Command Line Tool…** (see [Building from source](#building-from-source)), Services, **Hide Takewise** (⌘H), **Hide Others** (⌥⌘H), **Show All**, and **Quit Takewise** (⌘Q). Quitting refuses while a take or passage exists only in memory, as closing a window does (see the `record` notes above).
- **File:** **Open Project…** (⌘O) opens the folder picker in whichever window is in front, as in the start window: a project opens in its own window (or comes to the front), and a folder that is no project yet goes on in a start window, which asks for the film.
- **Window:** **Minimize** (⌘M) and **Zoom** for the window in front.
- **Help:** **Takewise Help** opens the README on GitHub, **Keyboard Shortcuts** its keys, **Release Notes** the GitHub release of the version running, and **Report an Issue…** a new issue.

## Passages in the window

- **Shift+Space** records from the current line through the end of its passage as one take: one capture and one film playback, with the pre-roll and the count-in only before the first line. The prompter shows each line from the moment the film reaches its start, with its text, pace guide, note and next line, starting at its top; for 1.5 s of film after that, the line just read stays above it, dimmed on one row (cut short with … when long), so a reader running a little late can finish it. That row is kept, empty, for the whole passage take, so the line being read never moves; the line list marks the line being read and the current line follows it. The take stops `[record] tail_s` after the last line's slot (or the film's end), with Space or Shift+Space, or when the capture fails. The lines are read as they were when the take started, so M is off during a passage take. With one line left in the passage, Shift+Space records that line as Space does. Space and R always record the current line alone.
- When the take stops, the passage is saved whole as `takes/.passages/<id>.wav` and then cut into one take per line; the window says "cutting it into takes…" and then how many lines were recorded. A line the recording did not reach, or stopped on before anything of it was read, gets no take and is named. When the take ran to its end, the current line goes back to the line it started on, so Shift+Space reads the whole passage again; when you stopped it, the current line stays on the line being read, so Shift+Space there picks the passage up again from that line. A take cut from a passage says so in the take list ("passage 2/3": the second of its three pieces). The cuts follow the cues within about a second, so missing or extra words on both neighbours of a cut after a passage take mean the read ran off the cues there; the passage file itself is intact (Shift+P plays it, and a passage chosen whole exports as it was read).
- **Shift+P** plays the selected take's passage, locked to the film, to its end: from the passage's first line, the passage file from its own first sample; from a later line, the film starts one pre-roll before that line's take (or before the line, if it starts earlier) and the passage file plays from the matching sample, so the end of the line before leads in. P still plays one take in context; for a take cut from a passage it plays through the take's own end, which can lie past its line's slot, and the tail. Space, P or Shift+P stops either.
- **Shift+Enter** chooses the selected take's passage for every line it has a take of, all of them or none, as `takewise choose --passage` does; the window says how many lines were chosen and which lines of the passage kept their choice. Enter still chooses one take.
- A passage that cannot be saved (a full or failing disk) is kept in memory and saved again every two seconds, as a take is; the window does not close while it is only in memory, until it has a rescue copy (see [Rescued audio](#rescued-audio)). Opening a project also finishes a passage that a crash interrupted, as `status --repair` does.

## Rescued audio

A take or passage that cannot be saved into its project stays in memory while the window keeps trying. When the window has to go before that works, it writes a rescue copy that does not depend on the project's disk:

```text
~/Library/Application Support/Takewise/rescue/<project folder name>-<timestamp>/
  001-take-<line>.wav     the audio: 48 kHz mono 24-bit, as a take's
  001-take-<line>.json    which project and line, and what the project would have stored with it
  002-passage.wav         a passage recorded in one go, whole
  002-passage.json
```

`<line>` is the line's id; an id longer than 80 bytes is cut to its beginning and eight hex digits of a hash, and the JSON file's `lines` has it whole (a project folder name longer than 200 bytes is cut the same way, and `project` has the whole path). A name is used once: a copy never replaces a file that is in the folder, and a folder holds everything one window could not save, which can be several takes and passages.

(`rescue/` lies beside the settings file, so beside the file `TAKEWISE_SETTINGS` names when that is set.)

This happens in two cases, and only for audio that is not whole on the project's disk either:

- You close the window, or quit with ⌘Q, a second time while saving still fails. The first time the window refuses and names the folder; the second time it writes the copy, syncs it and closes. If the copy cannot be written either, the window stays open and keeps the audio.
- The app is quit from outside (the Dock's Quit, a logout, a shutdown). macOS tells the app only once that is underway, so the window cannot refuse: it tries once more to save, then writes the copy. If the copy cannot be written either, because the project's disk and the disk of the rescue folder are both full or gone, the audio that was only in memory is lost: nothing can hold a quit from outside. Closing the window or ⌘Q refuses instead and keeps the audio. So when the window says a take is only in memory, free disk space first, and do not quit from the Dock, log out or shut down until it is saved.

The window prints where the copy is, the next window opened on the project says so, and `takewise status` lists it as a `rescued-audio` notice until the folder is removed. Nothing removes a rescue copy or brings it back on its own. A rescue copy is the whole recording; if the project also adopts a shorter take of the same reading after a crash (marked `recovered`, from what had reached its disk), the rescue copy is the complete one.

To bring the audio back once the project can be written again, put each copy's two files where a take that a crash interrupted would lie, and let a repair adopt them. One folder can hold several recordings, so go through all of it. First see what it holds:

```sh
rescue="$HOME/Library/Application Support/Takewise/rescue/<folder>"
ls "$rescue"
jq -r '"\(.audio): \(.kind) of \(.lines | join(", ")), for \(.project)"' "$rescue"/*.json
```

Each JSON file names both places in `restore`, relative to the project folder, and carries the file to write as `sidecar`. Restore every recording in the folder, then run one repair. The steps stop at the first one that fails, so nothing is left half restored without you seeing it:

```sh
(
  set -e
  cd "<project>.takewise"
  for json in "$rescue"/*.json; do
    audio="$(jq -r .restore.audio "$json")"
    mkdir -p "$(dirname "$audio")"
    cp "$rescue/$(jq -r .audio "$json")" "$audio"
    jq .sidecar "$json" > "$(jq -r .restore.sidecar "$json")"
    echo "staged $(jq -r .audio "$json")"
  done
  report="$(takewise status --repair --json .)"
  printf '%s\n' "$report" | jq -e .data.repair
)
```

The parentheses keep `set -e` to these steps, so a failure stops them without closing your terminal. Run them once per folder: running them again stages every recording a second time; the repair adopts each take again as another take, and a passage that is already published is reported again with no new takes and leaves its staged audio behind as a stray partial file under `takes/.passages/`. If a step failed, fix the cause, remove what that run staged for the recording it stopped at, and stage the remaining recordings only.

The repair numbers each take as its line's next one, and publishes each passage and cuts it into its takes, all marked `recovered`. Do this with the window closed, or let the window do the repair when it opens. Then check every recording against the repair's report: each staged take is in `adopted` (its line and new number), and each staged passage in `passages_published`, with its takes in `pieces`. A recording missing there is not back yet; its files are still in the rescue folder. Only when every recording is accounted for, delete the rescue folder, which removes all its recordings at once; until it is gone, `status` keeps listing it.

A WAV in the folder with no JSON file of the same name is audio whose JSON file could not be written (the disk failed between the two). The window says so as it goes, and `status` names such files in the folder's notice. Nothing says where that audio belongs in the project, so a repair cannot adopt it: listen to it, and keep it somewhere else if you need it, before you delete the folder.

The JSON file's other fields say what the copy is: `kind` (`take` or `passage`), `project` (the folder it was recorded for), `rescued_at`, `audio`, `sample_rate`, `samples` and `lines`; inside `sidecar` are the line's `snapshot` (the text read and its slot) and the take's `line_offset_s`, or for a passage its `lines` with their snapshots and `first_sample_film_s`, which place the audio in the film.

## Sound: the audio panel and meters

Press **A** in the recording window for the audio panel. It also opens by itself when the project's input is missing, not chosen, or not running at 48 kHz, and says so in plain words; recording stays off until that is fixed.

- **Input, channel and output.** Pick the input device and the output the film plays through; takes and passages played with P and Shift+P play there too. While the chosen output is not connected, P, Shift+P and Space refuse and say so, rather than play through the system output (a take, because the film would play out loud into the microphone), and the panel marks it; once it is connected again (or another is chosen in `project.toml`), the window plays through it within two seconds, and every playback and take sets it again before it starts. A playback whose output goes away stops. A take whose output goes away records on and is kept; the window says afterwards that the film may have played elsewhere during it. Without a chosen output, everything plays through the system output. Every channel of the input has its own live meter: speak, and the channel that moves carries your microphone (on the RØDECaster Duo that depends on RØDE Central's routing); click it to record from it. An input at another rate offers **Switch to 48 kHz**, which sets the device's rate as Audio MIDI Setup would, or says why the device refused. Device changes apply between takes; during a take the pickers are disabled. The choices are saved in `project.toml` (`[input]`, `[output]`) and as the defaults for new projects in `~/Library/Application Support/Takewise/settings.toml`.
- **Levels.** Always on screen under the takes, not in the panel: **Film**, how loud the film plays (−60 to 0 dB, `[record] film_gain_db`), and **Voice**, how loud takes and passages play back with P and Shift+P (−60 to 0 dB, `[record] voice_gain_db`, 0 dB in projects made before 0.2.1; export never uses it). Once monitoring can run, **Monitor** joins them (−60 to +6 dB, `[monitor] volume_db`). Drag a slider, or use the keys that match the character you type, so they work on QWERTY and QWERTZ alike: `-` and `+` for the film, `,` and `.` for the monitor, 1 dB per press; the keys move the sliders. While monitoring cannot run, `,` and `.` change nothing and say why. A change is heard at once, also during a take or a playback, and is saved to `project.toml` half a second after it rests, between takes, and when the window closes. Only the levels changed in the window are written, so a level an agent changed in the file meanwhile is kept, and heard once the window reloads; a level that cannot be saved is tried again every 2 s. A level outside its range in the file is used at the nearest end of it. While the latency measurement (L, or the setup check's last step) plays its beeps, they play at 0 dB: the Film slider still moves, and the film gets that level once the measurement ends.
- **Meters.** The input meter holds its peak for 1.5 s over a shaded target band from −18 to −6 dBFS. The near-clipping light turns red at −1 dBFS and stays red until **K** or the next take. A take whose samples reached −0.1 dBFS says "clipped" in its row.
- **Monitoring (H)** is not available yet: it waits for a test on a real interface with wired headphones, which proves it adds no dropouts and does not move the takes. Until then the panel's switch stays off with that reason, and H says so. If your interface has direct (hardware) monitoring, use it to hear yourself; when software monitoring arrives, leave it off with direct monitoring on, or you will hear yourself twice. Monitoring will never change what is recorded.

## The setup check

Press **C** in the recording window. The window offers it, with a line above the keys, when no setup check has run on the project or the devices changed since; it never opens by itself and never during a take. It walks through four steps (Enter goes on, Esc closes):

1. **Devices:** the input, channel and output (change them in the audio panel, A). Speakers are flagged: use wired headphones. Bluetooth headphones are flagged too: their delay can change after reconnecting, which the latency measurement (L) corrects, and wired headphones are more reliable. The Mac's headphone jack is not flagged; when the Mac's built-in output does not say whether it plays through the speakers or the jack, the warning starts "If this is the Mac's speakers".
2. **Voice:** press Space and read the sentence on screen. You get the peak and the average speech level, any clipping, and the gain change on your interface that puts the peaks near −10 dBFS; read again until it says the level fits. Hints for popped consonants (a pop filter, or the mic slightly off-axis) and a boomy sound (a little further from the mic) never block anything.
3. **Room:** press Space and stay quiet for five seconds. You get the room's noise floor and how far your voice stands above it (40 dB or more good, 30–40 acceptable, below 30 noisy, with tips), and mains hum when it is there. The recording is kept as room tone in `takes/.room/`, which `clean` export uses for noise reduction on takes recorded on the same input, channel and (local) day at the same gain.
4. **Latency:** only when the project has no latency calibration for the devices in use, or its calibration was copied from an earlier measurement and the output is Bluetooth. Hold your headphones against the microphone and press Space: ten beeps play through the output for about 15 seconds while the input records them, as `takewise calibrate --write` does. A consistent measurement is stored as `[input] latency_offset_ms` with the devices it was measured on, and Enter closes the setup check; otherwise the step says why and nothing is written (Space measures again, Enter finishes without it).

Press **L** to measure the latency again at any time between takes, whatever is stored: it opens this latency step alone, and closes once a measurement is stored, saying what it stored (Esc closes it without one). C still runs the whole check.

The results go to `[setup]` in `project.toml`. Every take's check also compares its speech with the noise in its own pre-roll: less than 30 dB apart gives `listen` with `background-noise`.

### Remembered across projects

The latency measurements and setup checks are also kept in `~/Library/Application Support/Takewise/remembered.json`, beside `settings.toml` (beside the file `TAKEWISE_SETTINGS` names, when set), with copies of the room tones in `rooms/` next to it. `settings.toml` is never rewritten for this.

- **Latency.** Every stored measurement (`takewise calibrate --write`, or the setup check's latency step) is remembered for its exact input, output and capture buffer size; a newer one replaces it. Opening a project also remembers its own measurement when nothing newer is remembered for its devices. When the window opens, and whenever the devices or the buffer in use change, a project without a calibration that fits them gets the one remembered for exactly those devices and buffer size: it is written into `[input] latency_offset_ms` and `[calibration]` with `from = "remembered"`. A project that got its offset this way also gets a newer measurement for the same devices once one is remembered; an offset measured in the project itself stays. A project's own fitting measurement always wins, an offset is never applied to other devices or another buffer size, and `init` copies nothing. Nothing is copied either into a project whose devices or channel were changed from elsewhere since the window read it (another window, or an edit of `project.toml`), until the window has read it again. A copied offset stays in use only while the output and the buffer size can be read and match: when one of them cannot (the interface is unplugged), takes are placed without it and `status` shows `calibration-stale` until the devices are known again. The audio panel and `status` then say "latency from an earlier measurement on these devices (date)". For a Bluetooth output the panel adds that its delay can change after reconnecting: if takes sound late, press L to measure it again (15 s). It says so for every latency in use on a Bluetooth output, also one measured in the project itself; for a copied one, C's setup check also offers its latency step.
- **Setup check.** After each setup check, its result is remembered for its exact input, channel and output, with a copy of its room tone; room tones from earlier days are removed. A project with no setup check from today for the devices in use adopts one remembered from today: its room tone is copied into `takes/.room/`, then `[setup]` is written with `from = "remembered"`. `clean` export and the setup offer then work from the project's own files as usual; a take whose pre-roll noise floor is more than 6 dB from the room tone's still skips noise reduction.

Nothing is used while the project's input is not connected.

## Building from source

With Rust (pinned in `rust-toolchain.toml`) and [mise](https://mise.jdx.dev): `mise run build`, `mise run run -- <command>`, `mise run check`. Recording runs inside `Takewise.app`, so the microphone permission belongs to Takewise rather than to the terminal that started it: build the bundle with `mise run bundle` (a release build in `build/Takewise.app`, signed ad hoc, so macOS asks for the microphone again after each rebuild; set `TAKEWISE_SIGN_IDENTITY` to a Developer ID to keep the grant). `takewise record` looks for the bundle it runs in, then `$TAKEWISE_APP`, then `/Applications/Takewise.app`, then the repository's `build/Takewise.app`. Without Homebrew, **Takewise › Install Command Line Tool…** in the app links `~/.local/bin/takewise` to the binary inside the bundle; it never replaces a file that is not a link to a Takewise bundle. Releases are described in [RELEASE.md](../RELEASE.md).

## Regenerating the screenshots

The screenshots in [images/](images) and the loop `images/loop.webp` are made by `mise run screenshots` ([`scripts/screenshots`](../scripts/screenshots)), never by hand. It downloads NASA's public-domain "Earth Views from the International Space Station" once into the ignored `build/screenshots/` (checked against its SHA-256), cuts a 60-second demo film from it, and runs `takewise screenshots` (built with the cargo feature `screenshots`, never part of a release). That command builds a demo project with its own script, speaks its takes with macOS `say` (one with a wrong word, one too slow, one missing a word), checks them with the real checks, then opens recording windows on the project, hidden, with fake media: the film's frames come from a player that is only ever seeked, and the microphone is fed from the spoken files. Each window is put into its state through its own code and rendered offscreen, on the display with the highest scale, so the images stay sharp when the main display is a 1x monitor; the loop and `recording.png` come from a 1000×640 window so their text stays legible in the README's column. The loop records two takes in such a window, checked by the real checks (held back two seconds so "checking…" can be shown), renders a frame every 0.25 s of film from the count-in's 3 on and puts the frames together with `img2webp`, so the takes play at twice their speed; after each check it shows the list of takes close up, at the render's full resolution over the dimmed window. `social-preview.png` (1280×640, for the repository's settings, not linked from the README) sets a recording window beside the icon and name. Last, it runs the README's agent example for real with the same binary on a copy of the demo project (`status`, `judge`, `choose`, `export`; the transcript lands in `build/screenshots/cli/transcript.txt`) and draws the exported narration as `export.png`: one strip as long as the film, each line's id where the manifest's `dest_samples` place its take. Every image gets a thin light border and rounded corners; the script then compresses the PNGs (all but the icon) with `pngquant` (quality 85–98) and `oxipng`. Nothing plays, no microphone opens, no window appears. It needs `ffmpeg`, `whisper-cli`, the speech model, and `brew install webp pngquant oxipng`.

The app icon beside the README's title is `packaging/AppIcon.icns` exported at 256 px: `sips -s format png -Z 256 packaging/AppIcon.icns --out docs/images/icon.png`.
